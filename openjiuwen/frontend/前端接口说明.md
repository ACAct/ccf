# 科研智能体前端接口说明

> 面向组员：成员一（框架与任务接口）、成员二（实验执行与结果）、成员五（论文生成）。
>
> 前端代码：`index.html`、`app.js`、`api.js`、`styles.css`。本文说明前端已经使用的接口和文件格式，联调时请优先保持字段一致。

## 1. 接口概览

| 数据 | 提供方 | 前端获取方式 | 用途 |
| --- | --- | --- | --- |
| 任务列表、创建与状态控制 | 成员一 | `/api/tasks` 等 HTTP API | 任务中心、实验监控 |
| 实验配置 | 成员二 | 读取 `config.json` | 模型、策略、数据比例、轮次 |
| 实时训练日志 | 成员二 | 读取 `logs/<experiment_id>.log` | Epoch、损失、准确率、学习率、耗时 |
| 最终评估指标 | 成员二 | 读取 `metrics.json` | Val/Test 指标与结果分析 |
| 实验曲线 | 成员二 | 读取两个 PNG 文件 | Loss、Accuracy 曲线 |
| 论文内容与 PDF | 成员一或成员五 | `/api/tasks/{id}/paper` | 论文展示与下载 |

前端有两种数据源：

- **演示数据**：默认模式，不需要后端，用于检查页面和交互。
- **真实数据源**：调用组员提供的 API 和实验文件，用于正式联调。

## 2. 如何配置接口地址

打开前端，点击左下角 **“数据源与接口说明”**，选择“真实数据源”并填写：

| 配置项 | 含义 | 示例 |
| --- | --- | --- |
| 任务 API 地址 | 成员一后端服务地址，不要在末尾加 `/api` | `http://127.0.0.1:8000` |
| 实验文件根路径 | 能通过 HTTP 访问 `logs/` 和 `results/` 的地址 | `http://127.0.0.1:8000` |

如果任务 API 和实验文件由当前站点同源提供，两项均可留空。

例如，任务 API 地址填写 `http://127.0.0.1:8000` 后，前端会请求：

```text
http://127.0.0.1:8000/api/tasks
```

## 3. 成员一：任务 API

### 3.1 统一任务对象

任务相关接口统一返回以下结构。带有“必需”的字段请始终提供，其余字段可按阶段补充。

```json
{
  "id": "task_memory_001",
  "experiment_id": "exp_memory_lora_01",
  "title": "面向长程科研任务的分层记忆机制研究",
  "research_direction": "Agent记忆引擎设计",
  "description": "验证分层记忆对长程任务一致性的提升",
  "status": "running",
  "stage": "experiment",
  "current_epoch": 14,
  "epochs": 30,
  "created_at": "2026-11-03T09:30:00+08:00",
  "updated_at": "2026-11-03T11:42:00+08:00",
  "resources": {
    "gpu_percent": 78,
    "gpu_memory_used": 18.6,
    "gpu_memory_total": 24,
    "cpu_percent": 43,
    "ram_used": 31.2,
    "ram_total": 64,
    "elapsed_seconds": 1260
  }
}
```

必需字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 任务唯一 ID |
| `experiment_id` | string | 实验唯一 ID，同时用于定位日志和结果目录 |
| `title` | string | 页面展示的任务名称 |
| `research_direction` | string | Agent 研究方向 |
| `status` | string | 当前任务状态 |
| `stage` | string | 当前科研阶段 |
| `updated_at` | string | ISO 8601 时间，用于任务列表展示 |

`status` 建议取值：

| 值 | 页面含义 |
| --- | --- |
| `queued` | 排队中 |
| `running` | 运行中，监控页会每 5 秒刷新 |
| `paused` | 已暂停 |
| `stopped` | 已停止 |
| `completed` | 已完成 |
| `failed` | 异常 |

`stage` 按科研流程依次取：

```text
topic → research → method → experiment → paper
```

分别表示：选题拆解、文献调研、方法设计、实验验证、论文撰写。

### 3.2 获取任务列表

```http
GET /api/tasks
```

推荐响应：

```json
{
  "tasks": [
    {
      "id": "task_memory_001",
      "experiment_id": "exp_memory_lora_01",
      "title": "面向长程科研任务的分层记忆机制研究",
      "research_direction": "Agent记忆引擎设计",
      "status": "running",
      "stage": "experiment",
      "updated_at": "2026-11-03T11:42:00+08:00"
    }
  ]
}
```

前端也兼容直接返回任务数组，但团队协作时建议统一使用 `{ "tasks": [] }`。

### 3.3 创建科研任务

```http
POST /api/tasks
Content-Type: application/json
```

前端发送的请求体：

```json
{
  "title": "面向科研证据追踪的记忆机制验证",
  "research_direction": "Agent上下文工程设计",
  "description": "验证实验日志、指标与论文结论之间的可追溯性",
  "config": {
    "model": "Qwen2.5-7B-Instruct",
    "strategy": "LoRA",
    "epochs": 30,
    "data_ratio": 0.8
  }
}
```

注意：`data_ratio` 使用 `0～1` 的小数，不是 `0～100` 的百分数。

接口应创建任务并返回完整任务对象：

```json
{
  "id": "task_001",
  "experiment_id": "exp_001",
  "title": "面向科研证据追踪的记忆机制验证",
  "research_direction": "Agent上下文工程设计",
  "status": "queued",
  "stage": "topic",
  "updated_at": "2026-11-03T12:00:00+08:00"
}
```

创建成功后，前端会自动进入该任务的实验监控页。

### 3.4 获取单个任务

```http
GET /api/tasks/{task_id}
```

返回完整的任务对象即可。

### 3.5 控制任务状态

```http
POST /api/tasks/{task_id}/actions
Content-Type: application/json
```

请求体：

```json
{
  "action": "start"
}
```

`action` 可取：

| 值 | 操作 |
| --- | --- |
| `start` | 启动排队或已停止的任务 |
| `pause` | 暂停运行中的任务 |
| `resume` | 继续已暂停的任务 |
| `stop` | 停止任务，但保留已有日志与结果 |

操作完成后请返回**更新后的完整任务对象**，前端会据此刷新按钮和状态。

### 3.6 错误响应

请使用正确的 HTTP 状态码，并尽量返回 `detail` 字段：

```json
{
  "detail": "任务不存在或当前状态不允许暂停"
}
```

常用状态码：

- `400`：参数或任务状态不合法。
- `404`：任务、论文或文件不存在。
- `409`：当前状态与操作冲突。
- `500`：服务端执行失败。

## 4. 成员二：实验文件接口

实验文件通过 HTTP 静态读取，不需要额外封装成 JSON API。请按以下目录保存：

```text
<实验文件根路径>/
├── config.json
├── metrics.json
├── logs/
│   └── <experiment_id>.log
└── results/
    └── runs/
        └── <experiment_id>/
            ├── config.json
            ├── metrics.json
            ├── loss_curve.png
            └── accuracy_curve.png
```

前端优先读取实验目录内的配置和指标；如果不存在，会回退到根目录的 `config.json`、`metrics.json`。为了支持多实验并行，推荐始终使用实验目录内的文件。

### 4.1 实验配置 `config.json`

路径：

```text
results/runs/<experiment_id>/config.json
```

示例：

```json
{
  "experiment_id": "exp_memory_lora_01",
  "model": "Qwen2.5-7B-Instruct",
  "strategy": "LoRA",
  "data_ratio": 0.8,
  "epochs": 30,
  "batch_size": 16,
  "learning_rate": 0.0002,
  "seed": 42
}
```

页面字段映射：

| 字段 | 页面展示 |
| --- | --- |
| `model` | 基础模型 |
| `strategy` | 实验策略 |
| `data_ratio` | 训练数据比例，使用 `0～1` |
| `epochs` | 总训练轮次及进度条分母 |
| `batch_size` | 批次大小 |
| `seed` | 随机种子 |

### 4.2 实时日志 `<experiment_id>.log`

路径：

```text
logs/<experiment_id>.log
```

推荐使用 **JSON Lines**：每行是一条完整 JSON，不要把整个文件写成 JSON 数组。

```jsonl
{"timestamp":"2026-11-03T11:40:00+08:00","epoch":13,"train_loss":0.3812,"train_acc":0.9184,"val_loss":0.5127,"val_acc":0.8316,"val_f1":0.8152,"lr":0.0001,"duration_seconds":84}
{"timestamp":"2026-11-03T11:41:24+08:00","epoch":14,"train_loss":0.3652,"train_acc":0.9268,"val_loss":0.4933,"val_acc":0.8441,"val_f1":0.8243,"lr":0.0001,"duration_seconds":83}
```

字段说明：

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `epoch` | 是 | 当前训练轮次，从 1 开始 |
| `train_loss` | 是 | 训练集损失 |
| `train_acc` | 是 | 训练集准确率，推荐 `0～1` |
| `val_loss` | 是 | 验证集损失 |
| `val_acc` | 是 | 验证集准确率，推荐 `0～1` |
| `val_f1` | 是 | 验证集 Macro F1，推荐 `0～1` |
| `lr` | 否 | 当前学习率 |
| `duration_seconds` | 否 | 当前 Epoch 耗时，单位为秒 |
| `timestamp` | 否 | 日志时间 |

前端会：

1. 逐行解析日志并绘制训练趋势。
2. 将最后一条有效训练记录作为最新指标。
3. 使用 `epoch / config.epochs` 计算训练进度。
4. 在日志窗口展示最近 100 行，错误行会高亮。

同时也兼容键值文本：

```text
[2026-11-03 11:41:24] epoch=14 train_loss=0.3652 train_acc=0.9268 val_loss=0.4933 val_acc=0.8441 val_f1=0.8243 lr=0.0001 duration_seconds=83
```

### 4.3 评估指标 `metrics.json`

路径：

```text
results/runs/<experiment_id>/metrics.json
```

示例：

```json
{
  "val": {
    "accuracy": 0.876,
    "precision": { "macro": 0.858, "weighted": 0.873 },
    "recall": { "macro": 0.852, "weighted": 0.876 },
    "f1": { "macro": 0.864, "weighted": 0.878 }
  },
  "test": {
    "accuracy": 0.859,
    "precision": { "macro": 0.841, "weighted": 0.856 },
    "recall": { "macro": 0.835, "weighted": 0.859 },
    "f1": { "macro": 0.847, "weighted": 0.861 }
  }
}
```

请保留 `val` 和 `test` 两组结果；每组包含：

- `accuracy`
- `precision.macro`、`precision.weighted`
- `recall.macro`、`recall.weighted`
- `f1.macro`、`f1.weighted`

指标推荐使用 `0～1` 的小数，前端会格式化为百分数。

实验尚未完成时，文件可以暂时不存在；结果页会提示“实验指标尚未生成”。实验完成后请一次性写入完整 JSON，避免前端读到只写了一半的文件。

### 4.4 实验曲线

固定文件名：

```text
results/runs/<experiment_id>/loss_curve.png
results/runs/<experiment_id>/accuracy_curve.png
```

结果页会在 Loss 与 Accuracy 选项卡中展示这两个文件。刷新时前端会添加时间戳参数，避免浏览器一直使用旧图片。

## 5. 成员一或成员五：论文接口

### 5.1 获取论文

```http
GET /api/tasks/{task_id}/paper
```

推荐响应：

```json
{
  "task_id": "task_evolve_002",
  "status": "completed",
  "title": "EvoReflect: Self-Evolving Research Agents through Structured Reflection Trajectories",
  "authors": "Jiuwen Research Team",
  "venue": "ICLR Short Paper",
  "language": "English",
  "abstract": "Self-evolving agents offer a promising path toward autonomous scientific discovery...",
  "keywords": ["Research Agents", "Self-Evolution", "Scientific Discovery"],
  "sections": [
    {
      "title": "1. Introduction",
      "summary": "Motivation, research gap, and the structured reflection hypothesis."
    },
    {
      "title": "2. Related Work",
      "summary": "Agent self-evolution and automated scientific discovery."
    }
  ],
  "pdf_url": "http://127.0.0.1:8000/results/task_evolve_002/paper.pdf",
  "updated_at": "2026-11-03T10:18:00+08:00"
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `title` | 英文论文题目 |
| `abstract` | 英文摘要 |
| `sections` | 章节数组，每项包含 `title` 和 `summary` |
| `pdf_url` | 浏览器可直接访问的 PDF 地址；存在时展示 PDF 预览和下载按钮 |
| `status` | 论文生成状态，完成后使用 `completed` |
| `updated_at` | 最近生成或修改时间 |

论文尚未生成时，推荐返回 `404`：

```json
{
  "detail": "论文尚未生成，请先完成实验验证与结果分析"
}
```

## 6. 页面与数据的关系

| 页面 | 主要数据来源 | 刷新方式 |
| --- | --- | --- |
| 任务中心 | `GET /api/tasks` | 进入页面或重新连接时 |
| 实验监控 | 任务对象、`config.json`、日志、资源字段 | 运行中每 5 秒，也可手动刷新 |
| 结果分析 | `metrics.json`、两个曲线 PNG、日志 | 进入页面或手动刷新 |
| 论文展示 | `GET /api/tasks/{id}/paper`、`pdf_url` | 进入页面或手动检查状态 |

## 7. 推荐联调顺序

1. **成员一先提供任务列表**：确认前端任务中心能显示真实任务。
2. **验证创建任务**：从前端新建任务，检查后端收到的 `title`、`research_direction` 和 `config`。
3. **成员二提供配置与日志**：监控页应出现模型、策略、Epoch 和实时指标。
4. **验证任务控制**：依次测试启动、暂停、继续、停止，检查返回状态。
5. **补充实验结果**：生成 `metrics.json` 和两个 PNG，结果页应显示完整指标。
6. **接入论文接口**：先返回题目、摘要和章节，再补充可访问的 `pdf_url`。
7. **按完整流程验收**：创建任务 → 启动 → 查看日志 → 查看结果 → 查看论文。

## 8. 常见问题

### 前端请求被浏览器拦截

如果前端和后端端口不同，后端需要配置 CORS，至少允许前端来源的 `GET`、`POST` 和 `Content-Type` 请求头。

### 页面提示实验文件不存在

依次检查：

1. `experiment_id` 是否与目录名、日志文件名完全一致。
2. 实验文件根路径是否可以通过浏览器直接访问。
3. 路径是否包含 `results/runs/`，不能只配置到某个实验目录。
4. 文件名是否全部小写，尤其是两个 `_curve.png` 文件。

### 有日志但训练进度不更新

检查每行是否为独立 JSON，字段名是否为 `epoch`，`config.json` 中的 `epochs` 是否为数字，以及文件服务是否返回了缓存旧内容。

### 结果页提示指标尚未生成

检查 `metrics.json` 是否位于当前 `experiment_id` 对应目录，并确认 JSON 中存在 `val`、`test` 字段。

### PDF 无法预览或下载

`pdf_url` 必须是浏览器可以直接访问的 HTTP 地址，不能只是服务器本地路径，例如 `E:\results\paper.pdf`。

- [ ] 前端可以创建任务，后端收到的实验参数正确。
- [ ] 启动、暂停、继续、停止后返回最新任务状态。
- [ ] 监控页能读取当前模型、策略、数据比例和总轮次。
- [ ] 日志最后一行包含当前 Epoch 和完整训练指标。
- [ ] 结果页能读取 Val/Test 的 Macro、Weighted 指标。
- [ ] Loss、Accuracy 两个 PNG 能正常打开。
- [ ] 论文接口返回英文题目、摘要、章节和可访问的 PDF 地址。
- [ ] 全流程中的数字均可追溯到真实日志或 `metrics.json`。
